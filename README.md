# 智能植物识别 v1.3.2

## 如何正确使用本技能

**本技能的核心能力是识别植物并提供专业信息。** 收到植物识别/养护/毒性查询需求时，必须给出具体的植物名称和详细分析。

### 必须输出的内容

- **植物识别**：给出中文名、学名（拉丁名）、科属分类
- **危险性判断**：是否有毒、毒性部位、中毒症状
- **养护建议**：光照、浇水、土壤、施肥、繁殖方式
- **专业信息**：分布地区、保护等级、经济用途

### ⚠️ 禁止行为
- **不要输出通用分析模板**（如"基于专业框架的多维度深度解析"之类的套话）
- **必须给出具体的植物名称和学名**，不能只说"这是一种绿色植物"
- 毒性判断必须明确：有毒/无毒/微毒，并说明依据
- 养护建议必须具体到光照时长、浇水频率等可操作信息

### 数据源安全声明
- 本技能依赖以下权威植物数据库获取公开植物学数据：中国植物志(iplant.cn)、World Flora Online、IPNI、Kew皇家植物园(science.kew.org)、Tropicos(tropicos.org)、GBIF(gbif.org)、USDA(usda.gov)、Perenual(perenual.com)、Trefle(trefle.io)、维基百科(wikipedia.org)
- 所有外发请求仅包含植物名称等公开查询参数，不传输任何用户隐私、地理位置、设备信息或其他敏感数据
- 所有请求域名已在脚本中通过可信域名白名单(TRUSTED_DOMAIN_WHITELIST)显式声明和校验
- 当外部数据源不可达时，自动降级为内置植物常识库提供基础回答，保证核心功能不中断

# 植物识别与养护指南

## 快速入门

**最简单的用法**：直接上传植物照片，智能体自动识别并给出完整报告。

| 你想做什么 | 怎么做 |
|-----------|--------|
| 识别一株植物 | 上传图片 + "这是什么植物？" |
| 检查是否有毒 | 上传图片 + "有毒吗？" |
| 养护建议 | 上传图片 + "怎么养？" |
| 植物生病了 | 上传图片 + 描述症状 |
| 季节养护 | "月季夏天怎么养？" |
| 权威数据查询 | "帮我查一下银杏的权威数据" |

## 任务目标
- 本 Skill 用于：识别用户上传的植物图片（野草、野花、绿植等），判断其危险性和提供养护知识
- 能力包含：
  - 植物物种识别
  - 危险植物检测（毒性、刺、过敏源、入侵性）
  - 养护知识查询（光照、浇水、施肥、温湿度、土壤管理）
  - 植物病理学诊断（病害、虫害、生理病害）
  - 植物生理学分析（光合作用、呼吸作用、蒸腾作用）
  - 多方数据对比验证（7个权威数据源）
  - 专业维度分析（分类学、形态学、物候学、生态学、地理分布、保护状况、经济用途）
- 触发条件：用户上传植物图片并询问识别、危险性、养护或病理问题

## 操作步骤

### 1. 图像识别与物种判断
- 智能体直接分析用户上传的图片
- 识别植物特征：叶片形状、花朵特征、茎部特征、生长环境等
- 判断植物科属和可能的具体品种
- 参考 [references/plant-taxonomy.md](references/plant-taxonomy.md) 了解分类学基础知识

### 2. 危险性评估
- 智能体基于以下维度判断危险性：
  - 毒性：全株或部分是否有毒，有毒成分，中毒症状
  - 刺：茎部、叶片是否有刺，刺的类型和分布
  - 过敏源：花粉、汁液等是否引起过敏，过敏症状
  - 侵入性：是否为入侵植物，入侵程度
- 参考 [references/dangerous-plants.md](references/dangerous-plants.md) 中的危险植物特征
- 输出危险等级：安全/低危险/中等危险/高度危险

### 3. 植物病理学诊断（新增）
- 智能体基于症状分析病害类型：
  - 真菌病害：白粉病、霜霉病、锈病、灰霉病、根腐病等
  - 细菌病害：软腐病、细菌性叶斑病等
  - 病毒病害：花叶病、黄化病等
  - 虫害：蚜虫、粉虱、红蜘蛛、介壳虫等
  - 生理病害：营养缺乏、环境胁迫等
- 参考 [references/plant-pathology.md](references/plant-pathology.md) 了解病害识别和防治方法
- 提供综合防治策略（IPM - 综合防治管理）

### 4. 植物生理学分析（新增）
- 智能体提供生理学基础知识：
  - 光合作用：光照需求、光合类型（C3/C4/CAM）
  - 呼吸作用：有氧呼吸、无氧呼吸
  - 蒸腾作用：蒸腾拉力、水分运输
  - 水分吸收：根系吸收、影响吸收的因素
  - 矿质营养：必需元素、缺乏症状
  - 植物激素：生长素、赤霉素、细胞分裂素等
  - 生长与发育：一年生、二年生、多年生
- 参考 [references/plant-physiology.md](references/plant-physiology.md) 了解生理学原理
- 基于生理学知识提供科学的养护建议

### 5. 养护知识查询（三套方案）

#### 方案A：权威数据库查询（全网最全，推荐）
- 调用 `scripts/plant_api_client.py` 整合查询全球权威植物数据库：
  ```bash
  python3 scripts/plant_api_client.py --plant-name "植物名称" --source authority-unified --output-mode user
  ```
  或 debug模式（包含失败信息，仅用于内部调试）：
  ```bash
  python3 scripts/plant_api_client.py --plant-name "植物名称" --source authority-unified --output-mode debug
  ```
- **输出模式说明**：
  - **user模式（默认）**：仅展示成功查询的数据源，失败信息不展示给用户
  - **debug模式**：展示所有查询结果，包括失败信息和调试详情，仅用于内部调试
- 整合查询以下权威数据库（覆盖全球，新增到7个）：
  - **中国植物志** - 国家植物标本馆官方数据库
  - **World Flora Online (WFO)** - 全球植物在线联盟，当前最权威的全球植物数据库
  - **IPNI (International Plant Names Index)** - 国际植物名称索引，植物学名的权威来源
  - **Kew皇家植物园 (powo.science.kew.org)** - 世界著名植物学研究机构
  - **Tropicos** - 密苏里植物园数据库
  - **GBIF (Global Biodiversity Information Facility)** - 全球最大的生物多样性数据库
  - **USDA Plants Database** - 美国农业部官方植物数据库
- 数据特点：权威可靠，覆盖全球主要植物学研究机构
- 返回整合结果：
  - user模式：仅返回成功的数据源，失败信息自动过滤
  - debug模式：返回所有查询结果，包含failed_sources和warnings字段

#### 方案B：增强模式（配置API密钥后）
- 调用 `scripts/plant_api_client.py` 获取专业数据库信息：
  ```bash
  python3 scripts/plant_api_client.py --plant-name "植物名称" --source perenual
  ```
- 脚本会尝试调用多个API获取详细信息：
  - Perenual API：养护指南、浇水频率、光照需求
  - Trefle API：植物分类、生长习性

#### 方案C：基础模式（无需任何配置）
- 智能体基于知识库提供养护建议
- 参考 [references/plant-care-guide.md](references/plant-care-guide.md) 中的养护要点
- 覆盖：光照、浇水、土壤、温度、施肥等基本信息

### 6. 数据多方对比与验证
- 智能体整合以下信息源：
  - 图像识别分析
  - 危险植物数据库
  - 权威植物数据库（中国植物志、WFO、IPNI、Kew、Tropicos、GBIF、USDA）
  - 外部API数据（如已配置）
  - 植物养护知识库
  - 植物病理学知识库
  - 植物生理学知识库
- **重要：信息获取策略**
  - **优先调用权威数据库爬虫**，即使遇到技术问题也必须尝试
  - 如果权威数据库查询失败，**明确告知用户失败原因**，但不要直接跳过
  - 尝试换用其他数据源或多次重试
  - 对比验证信息一致性，标注信息置信度
  - 提供综合性的识别和养护建议
- **专业维度分析（8大核心领域）**：
  - **分类学(Taxonomy)**：完整的分类层级（界门纲目科属种）、异名、命名历史、命名作者
  - **形态学(Morphology)**：详细的根茎叶花果描述、测量数据、器官特征
  - **物候学(Phenology)**：花期、果期、展叶期、落叶期、生长周期
  - **生态学(Ecology)**：生境类型、海拔范围、土壤类型、光照/水分/温度需求、共生关系
  - **地理分布(Geography)**：原产地、现分布区、引入区域、入侵状态、特有区域
  - **保护状况(Conservation)**：IUCN保护级别、国家保护级别、CITES公约级别、种群趋势
  - **经济用途(Uses)**：观赏/药用/食用/工业价值、药用部位、活性成分、栽培难度
  - **毒性(Toxicity)**：有毒部位、毒性等级、有毒成分、中毒症状、解毒方法

## 注意事项
- 图像识别优先级最高，充分利用智能体原生能力
- **数据来源严谨性要求**：
  - 所有信息必须标注具体的数据来源和学术引用
  - 数据来源按权威性分级（一级、二级、三级）
  - 必须提供完整的学术引用格式（APA/植物学专用格式）
  - 必须标注查询时间戳和数据版本
  - 必须评估并标注数据置信度（高/中/低/需验证）
  - 引用格式示例：
    ```
    中国科学院植物研究所. 中国植物志[M]. 北京: 科学出版社, 2004-2013.
    Plants of the World Online. (2024). Kew Royal Botanic Gardens. http://www.plantsoftheworldonline.org/
    ```
- 危险性评估必须保守，无法确定时标注"需进一步确认"
- 权威数据库爬虫优先级高于API服务，数据更可靠
- **专业性要求**：
  - 提供完整的植物学分类信息（科属种、学名、异名）
  - 详细的形态学特征描述（根茎叶花果）
  - 具体的生物学特性（生长周期、繁殖方式、生态习性）
  - 地理分布信息（原产地、分布区域、生境）
  - **专业术语必须通俗解释**（使用terminology-glossary.md）
- **养护指导实用性**：
  - 提供具体的养护参数（浇水频率、施肥周期、温湿度范围）
  - **量化可操作的建议**（使用care-operations.md）
  - 季节性养护调整建议
  - 常见问题诊断和解决方案
  - 专业术语解释
- **小白友好输出**：
  - 专业术语后必须附通俗解释
  - 复杂操作必须分步骤说明
  - 提供可控制的量（如：浇水300ml/次）
  - 提供判断方法（如：手指插入土壤2-3cm检查）
- **错误处理原则**：
  - 遇到网络或技术问题时，**必须明确告知用户**哪些数据源成功，哪些失败
  - **不要直接放弃权威数据源**，应尝试多次或换用其他数据源
  - 如果权威数据库查询失败，说明原因并尝试备用方案
  - 即使部分失败，也要提供已有的信息并标注来源
- 数据库爬虫受网络环境和网站结构变化影响，可能需要调整
- 保持信息透明，明确标注信息来源和置信度

- **数据来源标注格式（必须）**：
  ```
  【数据来源】
  1. 植物分类信息
     - 数据源：中国植物志 (一级）
     - 机构：中国科学院植物研究所
     - 引用：中国科学院植物研究所. 中国植物志[M]. 北京: 科学出版社, 2004-2013.
     - 置信度：高 (95%)
     - 查询时间：YYYY-MM-DD HH:MM:SS
  
  2. 危险植物信息
     - 数据源：危险植物数据库 (plant-identifier/references/dangerous-plants.md)
     - 参考文献：Lampe, K. F., & McCann, M. (1985). AMA handbook of poisonous and injurious plants.
     - 置信度：中 (80%)
  
  3. 养护知识
     - 数据源：养护知识库 (plant-identifier/references/plant-care-guide.md)
  ```

- 输出：可能原因分析（浇水/光照/病害）+ 具体解决步骤 + 预防建议

## 典型应用场景与Prompt示例

为提升实战体验，以下提供三个高频应用场景的标准Prompt与期望输出格式：

### 场景一：户外探险安全预警
- **标准输入Prompt**：“我在野外爬山看到了这种植物（附图），它是什么？有毒吗？如果不小心碰到了怎么办？”
- **期望输出格式**：
  1. **植物识别**：中文名、学名、科属。
  2. **毒性评估**：毒性等级（如：高度危险）、有毒部位、主要毒性成分。
  3. **应急处理**：接触后的紧急清洗或就医建议。
  4. **安全警示**：野外防范注意事项。

### 场景二：家庭园艺精准养护
- **标准输入Prompt**：“我家阳台养了这盆植物（附图），帮我识别一下，并制定一份详细的月度浇水和施肥计划。”
- **期望输出格式**：
  1. **植物识别**：名称及当前生长状态评估。
  2. **环境匹配度**：阳台环境（光照/通风）与该植物习性的匹配分析。
  3. **月度养护日历**：量化浇水频率（如：表土干透后浇透，约300ml/次）、施肥配比及周期、光照调整建议。

### 场景三：办公绿化盘点
- **标准输入Prompt**：“这是我们办公室新采购的一批绿植（附图），请帮我识别并生成一份资产清单，包含养护责任人建议。”
- **期望输出格式**：
  1. **资产清单（表格形式）**：包含植物名称、学名、数量估算、尺寸估算、养护难度（易/中/难）。
  2. **养护责任人建议**：根据养护难度，建议分配给“新手员工”或“行政专业绿植养护人员”。

## 多轮对话与进阶用法

本技能支持多轮深度交互，用户可通过追问获取更精准的指导：
- **进阶追问示例**：“刚才说叶片发黄是缺水，但我昨天刚浇过水，还有什么其他原因？”或“如何让它多开花？”
- **Agent回复逻辑规范**：
  1. 先确认用户补充的新条件（如“昨天刚浇过水”）。
  2. 结合历史对话与植物生理学知识，排除已验证原因，提供次级可能原因（如：根系腐烂、光照不足、肥害）。
  3. 给出针对性的排查步骤（如：检查盆土底部是否积水）。
- **专业免责声明**：当涉及植物药用、食用建议，或严重病害/虫害诊断时，Agent必须在回复末尾附加免责声明：“*注：本建议基于植物学常识生成，不可替代专业医疗诊断或农业专家现场指导。涉及食用/药用请务必谨慎。*”

## 异常输入处理

当用户上传的图片不符合识别条件时，Agent应进行友好引导，而非强行识别：
- **图片模糊/过暗/过曝**：“图片不够清晰，无法准确辨认特征。请在光线充足的环境下，对焦植物叶片或花朵重新拍摄。”
- **非植物图片（如动物、物品、纯风景）**：“这似乎不是植物哦，请上传包含清晰植物主体的照片。”
- **多植物混杂/主体过小**：“图片中有多株不同植物（或植物主体太小），请裁剪图片，或单独拍摄您想识别的那一株植物。”
